# Contributing to LangChain.js Agent with Angular Frontend

We welcome contributions to this project! To ensure a smooth and collaborative development process, please follow these guidelines.

## How to Contribute

1.  **Fork the repository** on GitHub.
2.  **Clone your forked repository** to your local machine.
3.  **Create a new feature branch** for your changes.
4.  **Implement your changes** (code, tests, documentation).
5.  **Commit your changes** with clear and descriptive commit messages.
6.  **Push your branch** to your forked repository.
7.  **Open a Pull Request (PR)** to the `main` branch of the upstream repository.

## Getting Started

Before you begin, ensure you have the project set up locally. Refer to the `README.md` for detailed [Setup Instructions](README.md#setup-instructions).

## Branching Strategy

We use a simplified feature branching model:

-   **`main`**: This branch always contains the latest stable, production-ready code.
-   **Feature Branches**: For any new feature, bug fix, or enhancement, create a new branch off `main`. Name your branch descriptively, following the pattern `###-short-description` (e.g., `001-blog-generation`, `002-sophisticated-agents`, `003-enhanced-ui`).

## Commit Message Guidelines

We follow the [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) specification. This helps us maintain a clear commit history and automate changelog generation.

**Format**:

```
<type>(<scope>): <description>

[optional body]

[optional footer(s)]
```

**Examples**:
-   `feat(blog): Implement blog post generation feature`
-   `fix(backend): Resolve SerpAPI key not set error`
-   `docs(readme): Update setup instructions`
-   `chore(deps): Upgrade @angular/cli to latest version`

## Pull Request Guidelines

-   **Keep PRs focused**: Each PR should address a single feature, bug fix, or enhancement.
-   **Descriptive Title**: Use a clear and concise title that summarizes the PR's purpose.
-   **Detailed Description**: Provide a detailed description of your changes, including:
    -   What problem does this PR solve?
    -   How was it solved?
    -   Any relevant `spec.md`, `plan.md`, or `tasks.md` references.
    -   Screenshots or GIFs (for UI changes).
-   **Link to Issues**: If your PR addresses an open issue, link to it (e.g., `Closes #123`).
-   **Pass All Tests**: Ensure all unit, integration, and E2E tests pass locally before submitting.
-   **Code Review**: Your PR will be reviewed by maintainers. Be responsive to feedback and make necessary adjustments.

## Code Style and Quality

We enforce code style and quality using ESLint and Prettier. Please ensure your code adheres to these standards before submitting a PR.

-   **Backend**: Run `npm run lint` and `npm run format` in the `backend/` directory.
-   **Frontend**: Run `npm run lint` and `npm run format` in the `frontend/` directory.

## Testing

All new features and bug fixes should be accompanied by appropriate tests (unit, integration, E2E). Refer to the `README.md` for [Testing](README.md#testing) instructions.

## Reporting Bugs

If you find a bug, please open an issue on GitHub with a clear description, steps to reproduce, and expected behavior.

## Suggesting Enhancements

For new features or enhancements, please open an issue on GitHub to discuss your ideas before starting any development.
